# 参考卡：把多张参考压成一张可验证的送模图

## 为什么做

当前图像模型通常只接收一张参考图。人物创作真正缺的不是更多图库，而是把“身份、服装、姿态、场景”四种语义同时交给模型，并保证模型不会把参考板本身画成成图。

参考卡把已审片、已授权的本地素材压成一张图，再由提示词明确每个分区只提供一种信息。它解决三件事：

1. 单模型参考图限制；
2. 多张参考互相覆盖；
3. 身份、服装、姿态、场景的来源不可追溯。

## 分区与版式

- 槽位固定为身份、服装、姿态、场景；至少选择身份加任意一项。
- 两个槽位：1440×960 左右两格。
- 三个槽位：1440×1440，上排两格、下方整行。
- 四个槽位：1440×1440，左上身份、右上服装、左下姿态、右下场景。
- 间距 24px；每格封面裁切，避免拉扁。
- 不同槽位不能复用同一 assetId，前后端都校验，防止一张图同时冒充身份和服装。

## 数据与权利

合成结果写入资产库：

- `type: reference_image`，`confirmation: confirmed`，`rightsStatus: authorized`；
- `metadata.provenance: composed_reference_sheet`；
- `metadata.referenceSheet` 保存版式、槽位、提示词和 `rightsBasis`；
- `sourceAssetIds` 与每个来源建立 `derived_from` 关系；
- 素材只从 `canReuseAsset` 通过（已审片、已授权）的本地图片中选择。

## 提示词

`src/shared/reference-sheet.ts` 的 `buildReferenceSheetPrompt` 生成：

- 每格只读取一种信息，不复制版式；
- 身份以身份格为准、服装以服装格为准、姿态以姿态格为准、场景以场景格为准；
- 负面词包含拼贴、分屏、四宫格、参考板边框、分格线、文字、水印、多个主体；
- `applyReferenceSheetToCard` 把分区语义写进 `identityAnchor`、`bodyAndWardrobe`、`expressionAndPose`、`scene`、`mustKeep`、`avoid`。

这样，参考卡不是“把四张图拼起来给模型看”，而是一份带语义标签的送模协议。

## 入口

- 创作中心“参考卡组合”；
- 四槽位选择、预览、合成、查看送模提示词；
- 合成后“用这张卡开始创作”，进入单张创作第一步；
- 参考卡在预览中完整显示，不裁掉下半排；缩略图标记“四格参考卡”。

## 单参考模型回退（2026-10-31）

第一次把 1440×1440 四格参考板直接送 FLUX Kontext，模型原样复刻了 2×2 版式，右下角还补出一个陌生男性。这不是“参考卡生效”，而是版式泄漏，已判定为 P0 失败。

修正分两层：

1. **单参考模型**：检测资产的 `metadata.referenceSheet`，只取身份格原图作为参考；`stripReferenceSheetLayoutLanguage` 删除“参考板/四格/左上格/分屏/拼贴”等只在看合成板时才成立的句子，保留“无分屏/无边框”负面约束。job 的 `appliedReferenceAssetIds` 记录身份图，不再记录参考板。
2. **Gemini 多参考**：`gemini-image` 的 `maxReferences` 提高到 4；`GeminiProvider.refineImage` 按身份、服装、姿态、场景顺序送四张原图，提示词明确“只生成单幅画面，不要把版式、边框或分屏画进成图”。这样不依赖合成板本身送模，也能保留四层语义。

## 真实结果

- 单参考回退已真实出图：job `1eec1350-773b-4fb6-aff2-3f5105eff646`，资产 `dcfb98f8-e262-4a29-a01f-4bead636b9fb`，单幅、无拼贴、身份与身份格一致。
- 这张图只继承身份格，服装/姿态/场景仍来自文字约束；单参考模型做不到四格语义同时生效，这是能力边界，不是验收通过。
- Gemini 四图路径已通过 12 项适配器/共享模块测试与全量 394 项测试、build、package、verify；但实机多图请求尚未完成，因为生成会再次触发 macOS 钥匙串授权。

## 商用前必须解决

- 稳定代码签名：每次 ad-hoc 重打包都会让 macOS 把 App 当成新程序，`safeStorage` 反复请求授权。需要 Developer ID 或稳定的本地签名身份；这不是用户操作问题。
