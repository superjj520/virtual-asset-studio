# R19 可分享配方包（2026-11-02）

## 为什么做

配方之前只能留在本机数据库里。换一台机器、给同事复现、或者把自己调好的一套方法存档，都只能截图加复制粘贴。

对标库 anhao 的 ComfyUI 插件支持工作流导入导出，但那只是节点 JSON。我们这边的「配方」本身已经是一份完整方法（创作卡 + 提示词 + 适用条件 + 失效条件 + 验证记录），差的是一个能带出这台机器的文件格式。

## 配方包里有什么

`.recipe.json`，纯 JSON：

```json
{
  "format": "virtual-asset-studio/recipe",
  "version": 1,
  "exportedAt": "2026-11-02T04:00:00.000Z",
  "recipe": {
    "name": "午后侧逆光人像",
    "purpose": "角色主视觉",
    "applicability": "同一角色身份，只换场景与动作",
    "invalidationConditions": ["更换角色身份", "参考图审片失效"],
    "providerId": "flux",
    "card": { "intent": "…", "scene": "…", "aspectRatio": "2:3", "referenceAssetIds": [] },
    "prompt": "a short-haired woman, backlit by afternoon sun",
    "negative": "plastic skin, text, watermark",
    "evidence": ["曾用于三张候选"]
  }
}
```

### 导出时剥掉什么

| 字段 | 处理 | 原因 |
| --- | --- | --- |
| `card.referenceAssetIds` | 清空 | 图片是本地资产，带出去只会指向不存在的记录 |
| `card.referenceBindings` | 删除 | 同上 |
| `card.projectId` | 删除 | 项目是这台机器的事 |
| `sourceAssetIds` | 不进包 | 同上 |
| `id` / `createdAt` / `updatedAt` | 不进包 | 导入方会重新生成 |
| `status` | 不进包 | 别的机器没验证过，导入后一律是「待验证」 |

方法本身全部保留：创作卡所有文本字段、画幅、画风、模型偏好、提示词、负向提示词、适用与失效条件、验证记录。

### 导入时再剥一次

别人手改过的包可能又把 `referenceAssetIds` 塞回来。导入时会再清一次，并给出提示「配方包里的参考图引用已清空：图片是本地资产，需要在参考卡里重新选。」

缺字段的创作卡会被补成空串、画幅非法时回落 `1:1`——半张卡不该让界面崩掉。

## 校验

| 情况 | 报错 |
| --- | --- |
| 空文件 | 配方包是空的，请选择从本应用导出的 JSON 文件。 |
| 坏 JSON | 配方包不是有效的 JSON，请重新导出后再导入。 |
| `format` 不匹配 | 这不是虚拟资产创作工作台的配方包。 |
| `version` 更高 | 配方包版本 v2 比当前应用更新，请升级后再导入。 |
| 缺名称 | 配方包缺少配方名称。 |
| 缺创作卡 | 配方包缺少创作卡，导入后无法复用。 |
| 失效条件为空 | 不报错，补一条「导入后尚未在本机验证」，并提示用户 |

## 入口

- **导出**：模板域 → 方法卡 → 每张配方卡的「导出配方包」，选目录后写到 `目录/配方名.recipe.json`。
- **导入**：方法卡页头「导入配方包」，选文件后直接落库为待验证配方，列表刷新。

文件名会把 `\ / : * ? " < > |` 换成 `-`，避免导出时撞上路径分隔符。

## 顺手修掉的视觉缺陷

第一次真机截图发现操作区按钮被压成逐字竖排（「导出配方包」显示成 2 列 4 行）。原因：`.pattern-actions` 是 flex 但按钮允许收缩，文本在小宽度下逐字断行。

修法：`.pattern-actions` 加 `flex-wrap: wrap`，按钮加 `flex: 0 0 auto` 与 `white-space: nowrap`，下拉框单独给 `flex: 1 1 220px`。修完按钮横向排列，「淘汰配方」换到第二行属正常换行。

这条只有真机截图能发现——jsdom 不做布局。

## 已知限制

- 配方包**不含图片**。导出的配方换台机器后，参考图需要在参考卡里重新选——这是资产库的设计决定的，不是遗漏。
- 没有做「整库导出」，一次一条配方。批量分享留到以后。
- 导入不查重：同一条配方导入两次会得到两条，靠用户自己淘汰。
