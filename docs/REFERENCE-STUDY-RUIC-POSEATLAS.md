# 对标研究：RuiC-PoseAtlas 三图鉴

日期：2026-10-31

## 1. 看了什么

- 整理站：<https://github.com/HRuiCcc/RuiC-PoseAtlas>
- 在线版：<https://hruiccc.github.io/RuiC-PoseAtlas/>
- 上游素材站：
  - 人像：<https://ai-portrait-gallery.pages.dev/>
  - 衣装：<https://ai-costume-gallery.pages.dev/>
  - 姿势：<https://ai-pose-gallery.pages.dev/>

RuiC-PoseAtlas 把三套独立素材整理成三个图鉴：

| 图鉴 | 组织单位 | 规模 | 关键筛选 |
| --- | --- | --- | --- |
| 姿势 | 一组姿态 × 5 视角 | 288 组 / 1,439 张 | 系列、分类、角度、按姿势 / 单张 |
| 衣装 | 一套无人衣装 × 单品标签 | 1,407 套 | 季节、品类、色系、三语标签 |
| 人像 | 单张脸或造型 | 1,499 张 | 脸部 / 造型、发型、发型细节 |

它的核心不是“图多”，而是把三类参考拆成三个决策层：

> **姿势定骨架，衣装定皮相，人像定脸。**

## 2. 值得学的产品结构

### 2.1 参考不是一张图，而是分角色的一组图

上游站把参考拆成脸、衣装、姿势三条线，RuiC 用三个入口和三个数据模型承载。对创作工作台的直接启发：

- 现在的“参考图”是一张无角色含义的图，用户只能自己记住它是脸、衣服还是动作。
- 应升级为“参考图板”：最多 3 个槽位，每个槽位有明确用途——身份 / 造型 / 姿态。
- 生成时按用途分别送入提示词，模型更容易保持脸、衣服和构图。
- 槽位可以来自角色主参考、资产库、上传图；每个槽位都能一键替换和清空。

这是本次对标最值得抄的结构，不是视觉。

### 2.2 一组多视角比多张散图更好选

- 姿势以“组”为单位，卡片内直接放 5 个角度缩略图，点击切换。
- 大图页用方向键切角度，上下键切姿态，Esc 关闭。
- 相邻原图空闲预加载。

对我们的价值：

- 角色、场景、服装资产都可能有正面、侧面、背面、局部细节。
- 资产卡应支持“主图 + 变体条”，详情页支持角度切换，而不是把变体拆成互不相关的卡片。
- 系列镜头和三视图本来就需要多角度，这能直接复用。

### 2.3 标签就是索引，不是装饰

- 衣装每套拆成 8–10 个单品标签，标签同时承担展示、筛选、搜索。
- 搜索把中英日三种写法放进同一个索引。
- 每个筛选项都带数量，用户不用点进去才知道有没有结果。

我们的资产库目前只有名称、类型、来源和权利状态，缺少可检索的视觉属性。建议补：

- 人物：发型、发色、年龄感、脸型、气质
- 服装：品类、颜色、材质、版型、配饰
- 场景：室内 / 室外、时段、天气、风格
- 姿势：站 / 坐 / 跪 / 躺、单人 / 多人、镜头角度

### 2.4 浏览密度与首屏信息

- 桌面 5–6 列，移动 2 列。
- 首屏先给数量、分类 chips、搜索和结果计数，再进入图片。
- 移动端筛选折叠，横向滚动 chips，不堆一屏表单。
- 首屏只渲染一批，滚动续加载，避免一次塞进上千张。

我们的资产库在 390px 已经收窄了导入表单，但仍可继续压缩筛选，让素材卡更早出现。

### 2.5 工程化校验

RuiC 的 `npm run verify` 会检查：

- 条目数量与索引一致
- 三语字段完整
- 标签都在词典里
- 图片文件存在、尺寸和格式正确
- i18n 键完整、页面没有断链

我们刚经历过“生成资产在库里但页面看不到”的孤儿资产问题。应该增加 `npm run verify:assets`：

- 数据库每条图片资产都有对应文件
- managedPath 存在、尺寸可读、hash 与记录一致
- 缩略图/主图引用没有断
- 资产的角色、场景、项目绑定有效
- 生成任务与资产双向可追溯

### 2.6 可访问性与键盘

- 跳转链接、`aria-live` 结果计数、`aria-pressed` 状态
- 灯箱焦点陷阱、Esc 关闭、关闭后焦点归还
- `prefers-reduced-motion`

这些正好对应我们 P1 的无障碍缺口。

## 3. 不该直接抄的部分

- **不要改成零依赖静态站**：我们是本地 Electron 生产工具，数据库、任务、密钥、文件管理才是核心，不是图库网页。
- **不要把 288 张密集网格当创作首页**：图鉴适合“找参考”，我们的主流程仍是选择结果 → 比较方向 → 单变量调整。
- **不要现在做三语**：当前产品和验收都是中文优先；三语会放大文案和测试成本。
- **不要把原图塞进 Git**：我们用 managed-assets 和数据库，仓库只放代码和必要设计资产。
- **不要复制上游图片/数据**：姿势和衣装原作者禁止再分发图片本身；人像虽为 CC0，原站也请求不要转载文件。只学结构和交互，不搬素材。

## 4. 建议落到我们产品上的顺序

### 第一优先：参考图板

单张 / 剧情 / 系列的第一步，把单张“参考图”升级成三个有用途的槽位：

1. 身份参考（脸 / 角色主参考）
2. 造型参考（服装 / 整体造型）
3. 姿态参考（动作 / 构图）

每个槽位显示缩略图、来源和“更换 / 清空”，下方用一句摘要说明当前锁定了什么。生成请求按槽位组装参考，不再把多张图混成一个数组。

### 第二优先：资产变体组

资产从“一张图”升级为“一个组”：

- 主图 + 变体条（正面 / 侧面 / 背面 / 局部）
- 卡片显示变体数量
- 详情页支持方向键切换
- 选择资产时默认用主图，也可明确选某个变体

### 第三优先：标签与数量

- 资产增加结构化标签
- 筛选 chips 显示数量
- 搜索覆盖名称、标签、来源
- 空结果给出“清除筛选 / 导入素材”的唯一下一步

### 第四优先：verify:assets

先做只读校验脚本，不阻塞现有流程；发现孤儿资产、断文件、错误绑定时输出明确清单。

## 5. 结论

RuiC-PoseAtlas 最值得学的不是视觉，而是三件事：

1. **把参考拆成有语义的角色**（脸 / 衣装 / 姿势）。
2. **以组为单位组织多视角，而不是散图**。
3. **用标签、数量和校验把“能找到、能复用、不会丢”变成结构能力**。

这三件事和我们的“角色锁定 → 场景锁定 → 比较方向 → 保存复用”是同一条主线。下一步建议先做“参考图板”，它是投入最小、对生成结果和用户理解提升最大的一个改动。
