# 竞品 PK：anhao 三合一工作台 / RuiC PoseAtlas / 虚拟资产创作工作台

日期：2026-11-01  
方法：实站 1440×1000 与真实 390×844 视口截图、README/源码事实、本产品真实窗口与数据库验收记录。评分是“对目标用户的能力覆盖”，不是主观审美分。

## 一句话结论

- **anhao 是当前最强竞品**：它把“中文参考库 → 3+N 配方 → 5 个生成协议 → ComfyUI 插件”做成了完整、免费、可在线使用的闭环，内容规模和上手速度都明显领先。
- **RuiC 不是同层竞品**：它是优秀的三库参考层和前端样本，没有生成、资产、权利和版本能力；可以学，但不能拿它当商业对手。
- **我们不能在“图库数量 / 协议数量 / 免费 Web”这条战线上赢**。我们能赢的只有一件事：**把一次生成变成可追溯、可版本化、可复用的本地生产资产**。

## anhao 真正强在哪里

1. **内容即入口**：4,345 条数据、8,690 张本地图，首屏就能看到规模和样例，不需要先理解“工作台”。
2. **配方常驻**：底部 Dock 永远显示人像/服装/姿势三个槽位，选任何卡片都只是“加入配方”，不需要离开页面。
3. **协议覆盖**：Gemini、OpenAI、Qwen、Doubao、ComfyUI 都在一个界面里，BYOK，切换成本低。
4. **ComfyUI 原生插件**：不是导出 JSON，而是 4 个节点 + 4,345 张选图弹窗，直接进入专业工作流。
5. **免费 + 开源 + 4.6k stars/1.2k forks**：获客和信任成本极低，这是它最深的护城河之一。

## 它的硬伤（也就是我们的机会）

1. **没有资产系统**：生成结果进 IndexedDB 历史，不是可管理、可版本化、可交付的资产；没有权利状态、来源链、角色/场景绑定。
2. **没有生产流程**：没有任务、审片、批次、采用镜头集、系列归档；它解决“生成一张”，不解决“持续生产一个角色”。
3. **配方不是资产**：选完三槽生成后，配方没有成为可命名、可版本化、可分享的持久对象。
4. **密钥与合规**：API Key 存浏览器，依赖 `/api/proxy`；图片/数据许可不允许再分发，不能作为商业素材库打包。
5. **多参考能力未证明**：3+N 是入口能力，不等于模型真的能稳定同时理解身份/服装/姿态/场景；没有看到公开的真实一致性验收。
6. **单点体验**：没有本地项目管理、成本治理、失败重试、批量止损。

## RuiC 的价值

- 优势：五视角、三语、键盘浏览、深链、零依赖、`verify` 校验；是参考层交互的好样本。
- 局限：没有生成、资产、权利、版本、生产；姿势/衣装图片不可再分发。
- 结论：**学它的参考层，不要把它当竞品，也不要把它的图库当我们的护城河。**

## 我们唯一该守的护城河

不是“更多图”“更多模型”，而是：

> **参考配方 → 真实生成 → 审片与权利 → 资产版本 → 角色/场景复用 → 系列/批次交付**  
> 每一步都有来源、模型、种子、成本、权利状态和可回滚版本。

这是 anhao 没有、RuiC 更没有的“生产记录系统”。只有这条链做通，本产品才配叫“工作台”，否则只是更慢的生成器。

## 战略选择

### 不做

- 不做 8,690 张图库镜像：版权不允许，体积/维护成本高，且是对方最强项。
- 不追 5 家协议的数量：先把 fal 多参考 + 本地 ComfyUI 两条链路做稳。
- 不做免费 Web 流量产品：获客打不过 4.6k stars 的开源项目。

### 要做（按顺序）

**P0：让“参考卡”真的可用**
1. 用 fal Nano Banana 完成四图真实验收：单幅、身份一致、服装/姿态/场景至少各命中一项、无拼贴。
2. 如果模型仍不稳定，明确降级为“身份锚定 + 文字约束”，不要对外宣称四层语义都进了画面。
3. 每次生成记录实际发送的参考图 ID、最终 prompt、模型、种子、成本，UI 可查。

**P0：商用底座**
4. 稳定签名（自签证书或 Developer ID），钥匙串只授权一次；这是“可商用”门槛，不是优化项。
5. 失败可诊断、单任务重试、任务历史列表；现在是“最近一条恢复”，不是生产系统。

**P1：配方资产化**
6. 配方保存为资产：名称、四槽来源、提示词、模型、风格、版本、权利；可复制、可版本化、可再次生成。
7. 本地参考库导入：只导入元数据与用户自有图片，记录许可，不内置第三方图；这样既补齐内容，又不侵权。
8. 持久配方 Dock + 数量/标签筛选，学 anhao 的交互，不学它的图库。

**P1：专业工作流**
9. ComfyUI 桥接：先做“导出配方/工作流 JSON + 本地提交”，不做完整插件。
10. 12 个风格包可以后置；先把“角色一致性 + 资产链”打透。

**P2：差异化**
11. 系列/批次/交付包、成本预算、团队共享（本地优先，云端可选）。
12. 视频能力必须有镜头契约与首尾帧一致性，否则不做。

## 商业建议

- **不建议现在定价**。先把“配方资产 + 真实多参考 + 稳定签名”做成可演示的付费理由。
- 可行模型：桌面专业版一次性授权（含本地生产/资产链），团队版按席位订阅（共享资产库/审片/交付）；参考库只做导入器，不卖图。
- 关键指标：首个真实资产留存、配方复用率、每角色连续生成次数、从生成到归档的完成率、付费转化。

## 最终判断

- **打流量/内容规模：anhao 赢，别打。**
- **打单次生成体验：anhao 目前也赢，追平即可，不要投入过量。**
- **打“角色持续生产与可追溯资产”：我们有机会赢，但当前只完成了骨架，多参考真实出图和稳定签名是两道生死门。**
- **RuiC 只作为参考层与工程样本，不构成商业竞争。**

如果把资源继续投在“图库、协议数量、底层重构”上，这仗会输；投在“配方资产化 + 真实一致性 + 权利/版本/交付”上，才有胜算。
