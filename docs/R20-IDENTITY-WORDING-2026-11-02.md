# R20 修掉身份一致性上的文案自相矛盾（2026-11-02）

## 问题

候选 1 出现金发，而角色身份是黑发。查提示词生成链路时，在 `src/shared/reference-sheet.ts` 找到一处内部矛盾：

补充参考的说明写着---

> 只提取其材质、配饰、**发型轮廓**或光影等明确特征；发色、肤色、脸型、年龄、服装结构、姿态和场景必须严格沿用身份参考，补充参考不得覆盖。

同一句话里，既允许补充参考提供**发型轮廓**，又要求**发色与发型**只能来自身份参考。

而身份锚点那边写的是---

> 沿用参考板中的脸型、五官、肤色、年龄感与**发型**，不重新设计

两处都管发型：一处允许补充参考带，一处说只有身份参考算。模型遇到这种冲突描述时，会选择其中一条执行——金发就是这么来的（补充参考里那个人的发色被当成"发型轮廓"接受了）。

## 修法

三处提示词（单参考、双参考、应用到创作卡的补充参考说明）统一改成---

> 只提取其材质、配饰或光影等明确细节；**发色、发型**、肤色、脸型、年龄、服装结构、姿态和场景必须严格沿用身份/服装/姿态/场景参考，补充参考不得覆盖。

身份锚点那边补上"发色"---

> 沿用参考板中的脸型、五官、肤色、年龄感、**发色与发型走向**，不重新设计

改动原则：把"发型"从一个来源升级为唯一来源（身份参考），补充参考只保留材质、配饰、光影这三类不会引起身份漂移的信息。

## 证据

- `src/shared/reference-sheet.test.ts` 新增一项：断言补充参考说明里**不再出现"发型轮廓"**、必沿用清单含"发型、肤色、脸型"、身份锚点含"发色与发型走向"。
- `npm test`：**429 项全过**（上一轮 428）。
- `npm run build` 通过。

## 这只是根因之一

还有一条同样会导致漂移，但不在文案层：

`src/shared/character-slots.ts:192` 里身份锚点是---

```
identityAnchor: describe(byGroup("identity", "face", "hair", "skin"))
```

`describe` 只取 `activeCharacterFacts` 中被 `characterFactIsUsable` 判定为**已确认且来源有效**的细项。也就是说：角色档案里填了发色，但那条细项还是草稿状态时，它**不会进入身份锚点**——卡上看不见，出图时模型就自由发挥。

这条需要一个"身份锚点缺少发色/过短时在创作卡上提示"的 UI，属于新增能力，单独一轮做。

## 不能声称的部分

这次修的是提示词里的逻辑矛盾，**没有跑真实出图验证**。要证明黑发不再变金发，必须用同一个角色、同一组参考、同一个种子跑一轮生成并肉眼比对。没跑之前，这条只能记为"已修复矛盾"，不能记"身份已稳定"。
