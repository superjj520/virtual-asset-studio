# 创作模块能力基准与补齐顺序

更新时间：2026-10-26

## 结论先行

`ourdream.ai` 是 AI 陪伴 / 角色扮演产品，不是虚拟资产生产工作台的直接竞品。它能提供参考的是**创作向导的流畅度**，不是它的聊天、语音、伴侣社区或成人内容。

创作模块的目标不是“做成 ourdream”，而是：

1. 创作向导达到同等流畅度：六步内完成、每步只做一个决策、大图选择、随时可退、随时可继续。
2. 在它没有做好的地方建立优势：身份版本、参考图语义、系列连续性、单变量回退、资产回流、重启恢复。
3. 不扩展聊天、语音通话、伴侣关系、云社区、视频生成；这些不属于当前产品边界。

一句话：**向导流畅度对标 ourdream，创作生命周期超过它。**

## 竞品拆解

### 已核验的 ourdream 创作能力

来源：[ourdream.ai](https://ourdream.ai/)、[OurDream AI Character Creation Guide](https://www.aicompanionlist.com/en/blog/ourdream-ai-character-creation-guide/)。

- 六步向导，顶部进度条，底部只有一个 `Next`。
- 第一步用大幅人像卡选择族裔，下面用肤色色板；不是长表单。
- 现实 / 动漫风格先定，再进入外观、性格、关系、声音。
- 外观是重点：脸、体型、发型、服装、配饰；性格排在图像之后。
- 可以跳过创建，直接从现成角色或现成世界开始。
- 官方建议先出 3–4 张静帧锁定脸，再进入视频；视频失败率高、重试消耗 token。
- 官方承认提示词保真度不是 100%：服装、姿势、背景细节会在两次生成间变化。
- 角色一致性是“多数时候可以”，不是资产级锁定。

### 它真正做对的四件事

1. **一次只问一个问题**：每屏只有一个主要决策，用户不会面对长表单。
2. **先看到结果类型**：族裔、风格、外观都用图片而不是抽象参数表达。
3. **允许不从头开始**：现成角色、现成世界、免费先试，降低第一次创作的成本。
4. **把失败成本说清楚**：先静帧后视频，重试要花 token，用户知道自己在为什么付费。

### 它没有解决、而我们必须解决的问题

- 角色身份只在一次生成内“大概一致”，没有可追溯版本和状态。
- 参考图没有“主参考 / 仅记录 / 实际送模”的语义区分。
- 没有系列镜头顺序、逐镜连续性、镜头级变量锁定。
- 没有资产回流、配方验证、项目 / 资产包 / 审片关系。
- 浏览器会话中断后，没有可解释的恢复路径。

## 我们要达到的程度

### 目标状态

用户在不看说明的情况下，可以完成：

1. 从四类结果中选一个，或从已有角色 / 场景 / 模板继续。
2. 六步内完成角色定义，每步只做一个主要决策，右侧始终能看到当前结果摘要。
3. 进入候选比较，看到整组方向、当前序列、每个镜头的变化，而不是只看单张图。
4. 只改一个变量，改完能返回、撤销、切换版本，不产生重复资产。
5. 保存为带来源、版本、角色 / 场景关系、审片状态的资产。
6. 退出应用再打开，回到原来的阶段和选择，继续创作。
7. 从资产直接开始下一轮，不需要重新填一遍。

### 五层能力模型

| 层 | 能力 | 目标验收 |
|---|---|---|
| L1 起点 | 四类入口、继续草稿、从资产 / 模板开始 | 首屏能回答“继续上次 / 从零 / 从已有资产”三条路 |
| L2 定义 | 角色六步、视觉卡片、单步单决策、实时摘要 | 六步内完成，任何一步退出后可恢复 |
| L3 比较 | 单图方向、系列整组方向、当前 vs 所选、变化计数 | 用户能说出“这组为什么不同、改了几个镜头” |
| L4 连续性 | 角色版本 / 状态、参考图语义、系列 2–6 镜、逐镜细项 | 换镜头不丢角色，换方向不截断序列 |
| L5 生命周期 | 保存、版本、撤销、资产回流、重启恢复 | 不重复资产，能从资产继续下一轮 |

### 判断

创作模块的“外观”已经接近甚至局部超过 ourdream；真正的差距不在再加字段，而在**创作生命周期**。

## 补齐顺序

### P0：R1 创作会话恢复

先做 R1，因为它是所有长流程的基础。用户已经愿意花六步做角色，如果退出应用就丢失，后面的比较、资产、复用都没有意义。

第一片范围：

- 保存最近一次创作的类型、阶段、任务和已选条件。
- 创作首页出现“继续上次创作”，显示类型、阶段和更新时间。
- 角色恢复草稿与步骤；单张 / 剧情 / 系列恢复已选条件与阶段。
- 重启应用后仍能看到并继续。

### P1：C3 角色衍生统一

把定妆、表情、动作、服装变体统一到同一套“锁定身份 → 只改变量 → 比较 → 保存”的骨架，复用角色版本和状态。

### P1：R2 撤销与版本切换

每次修改保留可回退点；候选 / 方向 / 逐镜调整都能撤销；版本切换不产生重复资产。

### P1：R3 资产回流

从资产详情直接“用此角色做新场景 / 用此画面继续调整 / 用此系列追加镜头”，并自动带入来源关系。

### P2：C4 / Q1 / Q2

清理重复入口和旧文案；统一创作、资产、审片、生产的组件密度；完成四条真实端到端与唯一应用发布。

## 明确不做

- 不做聊天、语音、伴侣关系、社区 Feed。
- 不做 ours 的成人内容分类、角色卡市场或订阅 token 体系。
- 不为了“像竞品”增加新的一级导航。
- 不在未接模型时声称已生成图片或已保证角色一致。

## 完成定义

只有 `docs/PRODUCT-ACCEPTANCE.md` 的 C1–C4、R1–R3、Q1–Q2 全部“已验收”，并且四条流程在真实 Mac 应用中完成选择、保存、重启、复用，才能说“创作模块补齐”。

## 证据边界

- ourdream 的能力来自公开官网与第三方指南，能证明其公开工作流，不证明其每次生成都成功。
- 本工作台的本地实现以代码、自动测试、真实 Electron 截图和重启验证为准。
- 本文件是产品判断，不是竞品功能承诺。
