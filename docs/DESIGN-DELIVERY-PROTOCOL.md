# 设计交付与视觉验收协议

## 目的

将“看到问题再修”改为稳定的交付流程。该协议适用于工作台的桌面端、H5 与未来手机端，所有设计决策必须能落到页面、组件、状态和真实截图。

## 1. 每项改动先写清的四件事

| 项目 | 必须回答的问题 |
| --- | --- |
| 工作域 | 创作、资产、生产、模板中的哪一域？ |
| 主任务 | 用户在这个页面最终要完成什么？ |
| 保持项 | 哪些对象、状态、数据或流程不能被这次修改破坏？ |
| 验收点 | 用什么尺寸、状态、截图和交互证明改动成立？ |

如果无法回答上述问题，先不进入界面实现。

## 2. 设计合同

### 信息层级

- 顶部持续表达当前项目。
- 一级工作域固定为创作、资产、生产、模板。
- 二级导航只呈现当前工作域的上下文功能。
- 页面标题回答“当前做什么”，正文说明回答“为什么”和“下一步”。
- 每页只保留一个高强调主操作；其他操作降低视觉权重。

### 页面模板

| 页面类型 | 必须结构 |
| --- | --- |
| 总览 | 标题、关键状态、当前对象、唯一下一步 |
| 目录 | 筛选、清单、详情检查器；手机替换为卡片与详情 Sheet/路由 |
| 编辑 | 主编辑区、检查/预览区、明确保存或生成动作 |
| 审片 | 候选比较、变化项、确认标准、锁定/淘汰动作 |
| 空状态 | 为空原因、最短说明、唯一可执行入口 |

### 不采用的模式

- 不使用营销页式超大留白、无任务价值的大标题或装饰性卡片墙。
- 不用“高级、唯美、科技感”等评价词替代具体对象、动作和状态。
- 不把桌面侧栏、复杂表格或鼠标悬停作为手机端的唯一交互。
- 不一次性修改多个不相干的问题；批注必须指向一个具体元素和预期变化。

## 3. 跨端适配规则

| 宽度与能力 | 导航 | 列表/详情 | 主操作 |
| --- | --- | --- | --- |
| 375–767px | 底部四域导航 | 卡片、抽屉或详情页 | 全宽或固定底部动作 |
| 768–1023px | 横向域导航或收起侧栏 | 一至两列 | 上下文工具栏 |
| 1024px 以上 | 左侧工作域栏 | 清单/表格 + 检查器 | 顶部工具栏 |

普通字号、间距和列数只使用 CSS 媒体查询或容器查询。只有导航、列表、详情的**结构不同**时，才在适配器内根据可用宽度切换。不得使用 User-Agent 判断设备。

## 4. 单点批注流程

1. 用截图或具体路径指出问题，例如“375px 时一级导航挤在顶部，主内容首屏被压缩”。
2. 将问题归类为信息层级、交互、响应式、可读性、状态反馈或性能。
3. 只修改该问题相关的组件与令牌。
4. 用同一尺寸重新截图，并检查相邻尺寸没有回归。
5. 记录已验证事实、未验证事实与下一步；不要用主观词替代证据。

## 5. 验收门槛

### 桌面工作台

- 1440px、1920px 截图。
- 默认、空、加载/提交中、失败、成功至少覆盖与本次改动相关的状态。
- 键盘焦点可见，主动作可判断，长名称不破坏布局。

### H5

- 375×812、430×932、768×1024、1024×768、1440×900。
- 检查安全区、横屏、缩放、底部栏与键盘出现后的内容可达性。
- 不出现横向滚动，触控目标不小于 44px。

### 原生手机端

- 小屏、大屏、平板、横屏、系统字体放大、深色模式、减少动态效果。
- 只有在真实设备或模拟器检查后，才可声称原生视觉验收完成。
