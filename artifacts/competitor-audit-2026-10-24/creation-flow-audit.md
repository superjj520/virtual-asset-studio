# 创作流程竞品核验与改造结论

## 核验范围

- 竞品：`https://ourdream.ai/create`
- 核验日期：2026-10-24
- 核验方式：官方公开创建页、官方功能说明与本地真实窗口逐步验收
- 本地对象：`虚拟资产创作工作台` 的创作入口、角色塑造、单张画面、剧情场景与系列镜头流程
- 本轮边界：只比较不依赖图片模型即可完成的创作规划与交互；不把模型生成质量计入结论

## 已确认的竞品创作结构

竞品公开创建页采用连续步骤，每一步只解决一个选择：

1. 顶部持续显示当前步骤与总步骤。
2. 首屏使用极少量的大图卡选择总体风格。
3. 后续页面使用人物特征图卡、肤色色样等高密度视觉选项。
4. 页面文案短，当前任务单一，主按钮唯一。
5. 公开说明中的完整角色创建覆盖外形、身体、角色信息、声线、性格、职业、关系与兴趣，而不是只完成一张外观图。
6. 高级信息默认收起，用户可以在基础选择完成后再补充问候语、情境和额外角色信息。
7. “实时状态”独立管理服装、地点、心情和关系温度，并区分用户可见字段与内部状态；字段带有更新规则，不只是静态标签。
8. 保存后的角色会继续进入聊天、图片与后续内容，不是一次性表单结果。

竞品优势的本质不是字段更多，而是把复杂角色设定压缩为连续、低认知负担的视觉决策。

## 当前工作台的产品转化

角色快速创作已重构为六步选择式流水线：

1. 起点：选择原创、已有角色或参考图，并从完整视觉方向中选择起点。
2. 基础：选择成年角色类型、年龄、人物特征和肤色。
3. 外形：在同一阶段完成脸型、眼神、瞳色、发型与发色。
4. 形体：选择身体比例、身高、体态、上身量感与下身轮廓。
5. 内核：通过“定位 / 关系 / 故事 / 表演 / 状态”五个子页选择职业、服装、性格、声线、关系、兴趣、人物原型、长期目标、内在冲突、默认开场、动作、表情、表演方向、默认场景和持续状态。
6. 完成：集中核对外形、内核、关系、默认情境与持续状态，并保存为可继续扩展的角色资产。

实现原则：

- 快速模式不要求填写长文本。
- 视觉卡片承担主要选择，标签和色样承担补充选择。
- 每一步只保留一个主要前进动作；复杂角色信息采用步骤内分组，不增加主流程长度。
- 选中状态、底部摘要和右侧角色预览同步更新。
- 持续状态由“当前值 + 更新规则 + 可见性”组成；默认包含心情、地点、服装和关系温度，并随角色状态版本持久化。
- 标准字段不足时可以在同一步添加自定义字段；字段名称、当前值、可见性和更新规则均可继续编辑，不把高级需求重新变成长表单。
- 未完成角色方案会自动保存在本机；退出或重启应用后回到原步骤，并提供明确的“重新开始”动作。
- 保存后进入可继续扩展的角色资产，而不是一次性结果。
- 精细塑造仍保留给需要完整控制的用户，不干扰快速流程。

同一交互原则已经延展到另外三条创作流水线：

- 单张画面：主体 → 造型 → 场景 → 输出。
- 剧情场景：演员 → 表演 → 剧情 → 输出。
- 系列镜头：角色 → 连续性 → 分镜 → 交付。

三条流程均使用样片、图卡、标签和色样完成主要决策；中间步骤原有的“直接建立”旁路已删除，用户必须经过最终输出或交付确认，页面只保留一个主要前进动作。

## 当前结论

角色快速创作这一条非模型流程，已经完成从“外形选择器”到“可持续角色资产建立流程”的结构性改造：人物外形、职业、性格、声线、关系、兴趣、故事驱动、内在冲突、默认开场、表演、默认情境和持续状态都进入同一条六步主流程，且不要求用户先写提示词。

当前仍不能宣称“整个产品已经全面匹敌竞品”。可以确认的是：在不依赖 AI 模型的角色创建、状态管理、草稿恢复和角色跨创作复用范围内，竞品的核心原则已经被转化为本产品自己的六步角色资产流水线，而不是照搬页面；自动化测试已经覆盖内核选择、标准与自定义状态、字段编辑、草稿恢复、保存归档与无模型调用，正式 Mac 包也完成了从起点到最终复核的真实点击回归。

角色跨创作复用不再停留在“选择一个衍生类型”：实机已经从已保存角色进入剧情场景工作台，界面自动恢复人物视觉基线、人物内核、关系、目标、冲突、默认开场和持续状态，并把剧情任务组织成四段可选择方向。用户先用场景图卡确认故事世界，再用剧情专属的单变量选项调整情绪、动作、空间、镜头或时间光线；最终可以直接建立场景档案和场景状态。方向页展示的图片明确标注为“基于当前角色视觉基线预演”，只承担本地规划与比较，不冒充角色母版、参考图或模型生成结果；没有视觉基线时改用纯文字方向卡，不再显示虚假的编号占位图。

本轮实机复核还发现并修复了三项会直接破坏“选择式创作”的问题：草稿提示让步骤条被裁切，组合参考板把相邻人物同时切进同一张选项卡，以及姿态和表情错误复用身体比例图、脸型图。修复后六步导航完整，底部唯一主操作不再被重复通知遮挡，人物选项一人一卡；姿态与表情改为与语义对应的图标和判断说明，选中结果会同步进入右侧预览和最终摘要。

Mac 桌面包的真实最小宽度是 1100px，而不是 CSS 中预留但桌面窗口无法触发的 900px。现已在 1100px 下逐页复核六个步骤，未发现横向重叠、主操作丢失或选择控件不可达。900px 以下仍属于未来 H5 / 手机运行形态的独立验收边界，不能用桌面包结论代替。

仍不能计为整个产品全面匹敌竞品的缺口：竞品登录后的角色保存、复用和动态状态路径仍缺少同深度证据；最终生成、社区与付费能力也尚未完成同口径比较。角色创建这一条非模型主流程已经具备与竞品正面对照的交互结构和本地闭环，但文档不会把局部通过外推为全产品胜出。

本轮原先列出的三个缺口——自定义状态字段与字段级编辑、快速创作草稿恢复、角色保存后的跨创作复用实机回归——现已闭环。跨创作复用已覆盖表情组与剧情场景；剧情场景还完成了场景选择、方向比较、单变量调整和场景资产沉淀，不再只验证静态角色卡。当前完整自动化回归为 60 个测试文件、271 项测试全部通过。尚未完成同口径比对的是竞品登录后的生成结果、社区与付费能力；真实模型结果质量也不用于评价本轮非模型创作流程。

角色管理页也完成了同一原则的回收：原版本把角色工作室和完整度检查器同时纵向铺开，用户进入角色后会同时看到“继续创作”和大量细项，任务焦点不清。当前版本改为两个互斥视图，默认进入“创作与复用”，只有主动选择“细节设定”时才加载身份、形体、五官、服装与证据。真实窗口确认两种视图均占满右侧可用宽度，角色列表保持稳定，切换后没有重复内容或空白占位。

## 后续验收门槛

1. 新用户不输入长文本即可完成角色、单图、场景和系列方案。
2. 每一步只有一个明确主操作。
3. 所有选择均即时反映在预览或当前方案摘要中。
