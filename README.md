# 虚拟资产创作工作台

本地运行的角色、场景、镜头与生成资产工作台。它把“灵感/参考图 → 结构化创作 → 候选比较 → 审片确认 → 母版与配方 → 项目交付”留在同一条可追溯链路中。

## 首次启动

```bash
npm install
npm run dev
```

`npm run dev` 会自动为 Electron 重建本地数据库驱动，然后启动桌面应用。请不要直接执行 `electron .`，否则在更新 Electron 后可能出现原生模块版本不匹配。

## 生成可双击打开的 Mac 应用

```bash
npm run release:mac
```

打包完成后，应用位于 `release/虚拟资产创作工作台-darwin-arm64/虚拟资产创作工作台.app`。这是仅供个人本机使用的临时签名版本；对外发布前仍需要 Apple 开发者签名与公证。

## 产品框架

工作台按四个工作域组织：

- **创作**：项目总览、新建创作任务、当前任务的设定与迭代。
- **资产**：角色档案、场景/服装/道具/参考图与已确认母版。
- **生产**：候选审片、镜头视频、生成队列与项目交付。
- **模板**：经过验证的创作配方、画面方向和外部学习来源。

每一次创作都会成为一个“创作任务”，它保存目标、角色/参考依据、必须保持项、使用的创作卡和最终候选结果；任务因此成为四个工作域之间的共同索引。

## 使用顺序

1. 在“创作 / 工作总览”选择项目，再从“新建任务”进入：选择新建角色、已保存角色或参考图；只填写一句话目标、人物依据和“必须保持”。这三项会先编译为可审查的创作基线，避免直接盲生图。
2. 在“资产 / 角色档案”选中一个人物，按身份、形体、脸部、发型、肤色、多角度、服装层次、表情、姿态和场景逐项填写；每项单独区分待确认、已确认、不适用，并可引用已归档素材和局部说明。用“肖像／全身设定／连续镜头”切换当前用途的必需清单。裤装、裙装、贴身衣物等不要求同时填写；有差异时新建造型变体，表情、动作和情境各自管理。旧卡文字会显示为未核验历史设定，可导入草稿后逐项确认，不会自动冒充人物事实。
3. 在“资产工作台”建立项目、导入人物/场景/服装/参考图并选择二级分类。导入默认“待核实使用权”；若直接选择已授权／原创，须填写依据。先建角色也没关系，后续在角色档案选一张已审片、权利明确的图作为主参考，系统会归入该角色资产包。逐项绑定素材证据；审片确认、使用权和角色肖像必需项都通过，才可锁定角色。证据撤下或授权撤销会让锁定失效。
4. 对已审片且使用权明确的参考图使用“视觉模型深度理解”，得到可编辑的结构化反推提示词；可回填创作卡或直接作为本轮提示词。图片送外部模型前仍要经过主进程校验。
5. 在“批量生产”只变化一个变量，选择 2–4 张结果横向比较；在资产工作台审片、确认并锁定母版。
6. 将可复用的创作卡保存到“创作配方”；只有经过实际结果确认的配方才应作为下一次创作起点。
7. “学习库”可登记公开 GitHub 仓库或具体公开网页来源；每条提示词仍需拆分、试用和验证，工作台不会全站抓取或绕过权限。
8. 导出项目会保留资产副本、项目简报、角色细项与素材证据、镜头合同和创作配方；清单使用包内相对路径，不包含素材的本机原始路径。

如果已有完整的人物资产包，可在“资产 / 角色档案”点击“导入人物资产包”，选择包含 9 张约定视图的 ZIP。系统会把图片复制进受管素材库，并新建一个“待命名”草稿角色；重复导入会复用相同素材但建立独立档案。导入结果不会自动成为主参考或母版，仍需逐项审片、确认使用权并明确主参考。

当前绘图适配器有参考图时仅将第一张实际送入 OpenAI，并只把这张记为成图来源；其他选择保存在任务提交记录中，不能视为已被模型参考。生成的候选默认处于权利待复核，不能自动当成原创母版。角色“可用”只针对当前用途与所选变体，不代表所有角度、服装和动作都已齐备。

升级旧数据库时，缺少授权依据的历史图片会改为“待核实”，原权利状态保留在审计字段中；旧角色包的素材会补齐项目关联。相同文件重复导入若权利状态或依据不一致，会提示先去素材库复核，不会静默沿用旧声明。素材权利仍是资产级声明，跨项目或对外用途是否涵盖在授权中，需要由使用者核实；项目导出是内部归档包，不是只含可公开使用素材的对外交付包。

API Key 仅以系统安全存储可用的加密形式保存在本机；没有 Key 时，资产整理、学习、反推提示词编排、提示词编译、配方和导出功能仍可使用。当前连接页支持 OpenAI（视觉理解、出图、修图、视频）、Gemini（出图、参考图修订）、FLUX（Black Forest Labs 直连文生图）、fal（`fal-ai/flux/schnell` 低成本文生图与 `fal-ai/flux-kontext/dev` 参考图修订）和 DeepSeek（创作对话与提示词规划）；首次配置某个模型后，未被用户显式指定的兼容图片路由会优先选择已配置模型（fal 优先图片与修图），不支持的能力不会硬映射。只有配置密钥并选择对应能力路由后才会调用远程服务。远程生成可能产生费用并上传参考内容，应用不会把演示结果当作已验证母版。

## 验证命令

```bash
npm test
npm run build
```

`npm run release:mac` 会依次完成测试、Electron 原生模块重建、构建、打包与签名校验。测试命令会临时切换到 Node 的本地原生模块版本；正式发布命令会在打包前自动切回 Electron 版本，以免出现本地数据库模块版本不匹配。
